# 踩坑记录(steelmap 开发实录)

项目开发中真实踩过并修复的坑,按类别编号。每条:症状 → 根因 → 修复 → 预防。
复查同类问题时按类别检索。原则:**静默失败是最大敌人,一切不变量用断言焊死**。

---

## 一、XRT 网络库(C 互操作)

### X1. Read 回调丢首块数据
- **症状**:小消息(8B)正常,大帧(>2048B)客户端永远收不到
- **根因**:Read 回调的数据装在 `pBuffer` 参数里,用 `xrtNetStreamRead` 从另一队列拉,
  每个完成式读取单元(ReadSize=2048)首块被丢。小消息恰好单单元不可见
- **修复**:`xrtNetBufSpans` + `xrtNetBufConsume` 直接消费回调缓冲(官方 tcp_server 示例)
- **预防**:跨 FFI 用库,先读官方示例的"惯用法",不要按 API 名望文生义

### X2. worker 内 send 重入派发事件 → 容器迭代器失效
- **症状**:客户端断开瞬间服务器随机崩,崩点在 broadcast 迭代 streams;加 printf 就不复现
- **根因**:在 worker 线程调 `xrtNetStreamSend`,XRT 检测"已在 worker"会**同步派发挂起的
  Close 事件** → 回调里 erase 正在迭代的 map → UAF(ASan 定位)
- **修复**:遍历容器前先拍快照到 vector 再操作
- **预防**:**一切回调体系里,凡"调用外部 API 时可能重入回调"的,迭代容器必须先拷贝**

### X3. 同款问题第二发:上层业务容器
- **症状**:per-connection 发送时崩溃
- **根因**:同 X2,但炸的是 ServerApp 的 `connPlayer`(不是 XRT 的 streams)
- **教训**:X2 修在传输层,X3 炸在业务层——同一机制在哪层迭代哪层遭殃

### X4. 流销毁时机 UAF
- **症状**:Close 回调里 Destroy → 后续崩溃;同拍末尾 Destroy → 仍崩
- **根因**:XRT 在 Close 回调返回后还有内部收尾,过早释放即 UAF
- **修复**:两段延迟(死名单隔一个完整 timer 节拍再 Destroy)
- **预防**:C 库的对象生命周期以文档+实验为准,不信"回调返回即安全"

### X5. 跨线程调用 send 静默丢弃
- **症状**:游戏线程发的快照永远到不了,worker 线程发的 Accept 正常
- **根因**:`xrtNetStreamSend` 仅在 worker 线程有效,跨线程调用返回失败且无异常
- **修复**:所有发送收敛到 worker 的 IO 回调内执行
- **预防**:事件驱动库的"线程亲和"契约要实测验证,不能假设

### X6. timer/post 在空闲 worker 上唤醒不可靠(平台差异)
- **症状**:Mac 上定时器全正常;Linux(WZU/null)上 server 的 grace 定时器静默不触发。
  单测定时器又正常(无连接场景)
- **根因**:XRT 引擎的 timer/post 依赖 worker 自唤醒机制,Linux 后端在特定空闲状态下丢拍
- **修复**:**自连踢泵**——游戏线程攒发送队列后向 127.0.0.1:listenPort 发起 TCP 连接,
  accept 事件(必然唤醒 worker)里冲刷发件箱。连接即踢,不发数据(数据会被 RST 吞)
- **预防**:任何依赖"库会主动唤醒"的机制都要在**目标平台+真实负载**下验证

### X7. 递归锁死锁(X2 的变种,最难的一个)
- **症状**:服务器进程活着、端口监听,但拒绝一切新连接(accept 不处理)
- **根因**:worker 的 onMessage 持 `std::mutex` → 内部 send → XRT 重入派发事件 →
  回调再进 onMessage → 同线程重锁非递归锁 = worker 永久卡死
- **修复**:`std::recursive_mutex`
- **预防**:"回调里调用会触发回调的 API"+非递归锁 = 必死。架构评审时专门检查这条链


### G8. 耳切三角化在尖刺环上死锁 → 放射扇形残缺(最难缠的一个)
- **症状**:澳大利亚等区域出现"从公共点放射的空心扇形碎片"、整批岛屿无填充
- **根因链**(三层,每层都以为是最后一层):
  1. Natural Earth 原始数据有自交环(64 个)
  2. shapely make_valid 的 exterior 带 A→B→A 折返尖刺,is_simple 检不出(相邻边共享端点被豁免)
  3. 耳切的"点在三角形内"阻挡测试若包含边界(非严格内部),折返点永远阻挡 → 死锁早退 → 残留三角形恰是放射扇形
- **修复**:数据端 buffer(0) 统一清尖刺 + 丢弃顽固环;耳切用**严格内部**阻挡(allPos||allNeg)、
  共线耳朵(cr==0)允许切、顶点去连续重复
- **方法论**:C++ 与 Python 验证脚本**必须逐行同构**,一轮分叉浪费一次终验;
  视觉模型会把"实心半岛+海湾"误读成"扇形碎片"——**结论必须像素级仲裁**(连通域/逐行连续性/直线度测量)

### G9. 截图回读双缓冲(Present 前后都黑/空)
- Present 后立即读 = 翻转后的空 buffer;正确做法:**Present 之前读**(同帧 drawable,ReadPixels 强制 flush)

## 二、SDL3 渲染(Mac/Metal,版本 3.4.16)

### S1. SDL_SetRenderDrawColor 收 Uint8,浮点被截 0
- 清屏纯黑、所有线条黑色不可见。浮点色必须用 `SDL_SetRenderDrawColorFloat`

### S2. 非索引 SDL_RenderGeometry 静默失败
- indices=nullptr 时返回 false 但**不报错不绘制**,和没写一样。始终传索引数组

### S3. 无纹理几何体在 Metal 后端不可靠
- texture=nullptr 不可靠。学 ImGui:统一绑 1×1 白纹理

### S4. SDL_RenderReadPixels 新版返回 SDL_Surface*
- API 变更,需 ConvertSurface 后读 pixels/pitch

### S5. RGBA8888 内存字节序是 A,B,G,R(小端)
- 转 BMP 时通道映射勿凭直觉;先 dump 字节再写转换

### S6. 截图双缓冲时机
- Present **前**读:拿到未提交的帧;Present **后立即**读:拿到从未绘制的新 backbuffer(全黑)。
- 修复:判定通过后再画 3 帧后读取

## 三、游戏逻辑

### G1. applyCommand 不设防
- 越权命令直接调用会改状态。修复:apply 内部强制再校验(validate→apply 双保险)

### G2. loadMapFile 忘初始化 provinceOwner
- "地图(内容)"与"归属(状态)"分离时的初始化遗漏 → AI/占领越界,服务器首拍崩且日志空
- 预防:加载器必须把**所有**派生状态字段重置,加断言检查尺寸

### G3. 幽灵行军
- 死单位(strength<=0)继续移动、可受令。修复:stepDay 与 validate 双拦截 + 测试盯着

### G4. 兵力负数(用户反馈)
- 伤害直接减产生 -N 显示。修复:阵亡即钳制到 0 + "永不为负"断言

### G5. 凹多边形扇形三角化溢出
- Voronoi 全凸没事,换真实国界(凹形)三角形溢出国界画进海里。修复:耳切三角化(ear clipping),
  且在地图缓存里只算一次。**教训:占位数据验证不了真实数据的形状假设**

### G6. 序列化字段顺序
- 写:邻接→地形→中心;读把地形插到了中心后 → 往返失败。预防:字段顺序改动要同步双端,
  往返测试必须存在(已有)

### G7. 大厅(tick=0)触发快照超时误判
- 超时判定挂在"tick 变化"上,大厅 tick 不涨 → 15 秒误杀。修复:改用快照序号判活

## 四、工具链与运维(时间黑洞区,数量最多)

### T1. python replace() 静默不匹配 —— 全场最费时
- 替换目标不匹配时不报错,补丁"看似成功"。空壳函数、丢失的 buildDefaultMap、
  没插进去的方法全是它干的
- **预防**:脚本打补丁必须 `assert old in src`;或改用带失败报告的编辑方式

### T2. pkill/pgrep -f 自匹配
- 模式匹配到自己所在 shell 的命令行 → 杀掉自己/误报存活。
  **预防**:用 `pkill -x 精确进程名`,或模式里避免包含自身命令行的字符串

### T3. start.sh 的 pkill 模式坏 → 僵尸服务器霸端口(犯了两次!)
- 新进程 listen 失败静默退出,旧进程一直服务,症状指向千万里之外
- **预防**:启动脚本必须验证新进程真的活着(`kill -0 $!` + 端口检查)

### T4. Text file busy
- 运行中的二进制不能覆写。部署顺序必须是:停进程 → scp → 启动

### T5. stdout 全缓冲
- 重定向到文件时 printf 全缓冲,崩溃/被杀时日志全丢,像"没开过口"。
  修复:`setvbuf(stdout, nullptr, _IOLBF, 0)`。
  另:`script`(pty)能行缓冲化,但会搞挂 ImGui 字体加载,别用

### T6. grep -c 假绿
- `cmake --build ... | grep -cE " error"` 在"构建根本没跑"时也输出 0。
  **预防**:构建验证要看产物存在(`ls build/xxx`),不能只看错误计数

### T7. 验收脚本自身也是代码,也会坏
- 提前杀服务器导致回放没落盘、跨地图对账(两个世界比哈希)、
  --shot-at 1 在大厅永不触发、rm 的目录通配……
- **预防**:验收脚本的失败要区分"产品坏了"还是"脚本坏了";先信日志不信推断

### T8. 环境干扰
- 机器掉线期间的所有诊断都是对着幽灵喊话;后台任务被回收;工作目录重置
- **预防**:诊断前先 ping/确认目标存活;重要部署用可存活的方式(nohup+crontab)

## 五、方法论(真正管用的招)

1. **确定性哈希对账**——"两个世界是否一致"变成一个数字的比较,三平台逐位对账,
   任何不一致立刻现形。这是本项目最强的调试武器
2. **二分法**:禁用 ImGui、FIN vs RST、零命令基线、单变量参数扫描——每次砍一半假设
3. **最小复现**:timer_test/post_test/combo_test,10 行程序复现 5000 行系统的问题
4. **字节级 dump**:帧头出现在第几块,胜过一万行推理
5. **ASan**:UAF 一发定位,Release 下的随机崩立即变确定栈。Guard Malloc 抓写越界
6. **像素验证**:颜色统计验证渲染(覆盖率/地形色/多色),不依赖肉眼
7. **每修一个 bug,加一条测试**:幽灵行军、负数兵力、越权……全有测试盯着,防复发
8. **补丁三问**:匹配了吗(assert)?改动对齐了吗(双端顺序)?工具自己坏了吗?

| 类别 | 数量 | 平均耗时 | 结论 |
|---|---|---|---|
| 语言层 UB(锁/迭代器/重入) | 4 | 高 | 最痛,架构评审可防 |
